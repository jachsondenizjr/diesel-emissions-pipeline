# ADR-001: Medallion Architecture over a flat BigQuery schema

**Date:** 2025
**Status:** Accepted
**Author:** Jachson Deniz

## Context

The pipeline ingests raw dynamometer data from WHSC test cycles and needs to serve two distinct consumers: a regulatory compliance dashboard (EPA Tier 4 / Euro VI) and an engine performance ranking view. Both consumers require different aggregation logic and freshness trade-offs. A flat schema was the simpler initial option.

## Decision

Adopt a three-layer Medallion Architecture: Bronze (raw ingest), Silver (cleaned + compliance flags), Gold (pre-aggregated marts). Regulatory compliance flags are calculated exclusively in the Silver dbt layer. All regulatory limits live in a single config.yaml passed to dbt via vars.

## Reasons

- A flat schema couples ingestion logic with business logic; any regulatory limit change would require touching ingestion code, not just transformation code.
- Two consumers with different freshness needs: Gold as materialized table for Looker Studio, Silver as view to avoid storage cost.
- Separating layers made it possible to run 45 dbt tests independently on each layer.

## Consequences

- One extra layer of indirection: debugging requires checking Bronze to Silver to Gold lineage.
- Accepted trade-off: correctness guarantees outweigh added complexity in a regulated domain where wrong numbers have real consequences.
